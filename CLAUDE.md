# MarketPollen

## Customer feature requests: scope first

We don't always build what a customer asks for. When a customer request comes in (forwarded email, call notes, etc.):

1. **Scope it before writing code.** For each item, write down what they asked, the underlying need behind it, and how the app behaves today (with file references).
2. **Understand the need fully.** Their proposed fix is a hint, not a spec. Ask clarifying questions where the need is unclear.
3. **Check fit for every customer.** MarketPollen serves multiple stores/organizations. A change should make sense for other customers too, not just the one asking. If it only fits one customer, consider a setting, a different design, or declining.
4. **Recommend**: build as asked / build differently / defer / decline, with rough effort. Separate clear bugs (fix) from feature requests (decide).
5. **Wait for Taylan's go-ahead** before implementing.
